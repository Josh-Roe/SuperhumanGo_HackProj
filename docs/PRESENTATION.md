## Two-minute pitch and live demo

| Time | Content | Evidence to show |
| --- | --- | --- |
| 0:00–0:20 | Name the user and problem. State the benefit in one sentence. | One concrete example |
| 0:20–0:35 | Explain the solution and why the agent belongs in the workflow. | A simple flow or screen |
| 0:35–1:25 | Run one complete happy path. Narrate the input, agent action, and result. | Actual working UI and Go integration |
| 1:25–1:45 | Explain implementation and one meaningful result. | Architecture and verified observation |
| 1:45–2:00 | State the current limitation and next step, then close with the user benefit. | One concise closing line |

Assign a presenter, demo operator, and backup presenter after the roster is complete. Rehearse to two minutes with the same data and screen arrangement used on stage.

## Canva handoff

The documentation/presentation owner prepares the copy and verified screenshots. Once the idea and visual direction are agreed, create or select a Canva design and record its editable link in the project issue. Ask the team to review the actual content before final export.

A small deck can use four slides: problem and user; solution and agent role; live-demo cue with a fallback screenshot; outcome, limits, and next step. Use short text and large screenshots that remain readable from the audience. Include source credits for reused assets and anonymize screenshots. Export a PDF backup and keep the demo video available locally.

Do not publish Canva links, assets, a deck, or the Devpost submission unless the corresponding task authorizes it. Keep the editable design link and exported files distinguishable so the team knows which version is current.

## Evidence and rehearsal checklist

- [ ] Story matches the implemented behavior and selected track.
- [ ] Agent's actual tool call and contribution are visible and explainable.
- [ ] Live path succeeds from a known starting state.
- [ ] Network/API failure has a clear response and a recorded fallback.
- [ ] Claims have measured evidence; placeholders and mocks are disclosed.
- [ ] No tokens, API keys, private messages, or personal data appear on screen.
- [ ] Demo link, repository instructions, video, and contributor credits are ready.
- [ ] Pitch fits two minutes and submission checklist is reviewed.
